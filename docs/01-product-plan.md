# Milkdown 编辑器 — 产品功能规划 (PRD)

| 项目     | 内容                                              |
| -------- | ------------------------------------------------- |
| 状态     | **v1.0 定稿**（评审通过 2026-08-31，决策 R1-R18） |
| 定位     | 类 Typora 的 WYSIWYG Markdown 写作工具            |
| 形态     | Web 应用（Vue 3），预留 Tauri 桌面化              |
| 基础技术 | @milkdown/kit + ProseMirror + remark              |
| 存储     | 本地优先（IndexedDB），预留云同步                 |

---

## 1. 产品定位

面向技术写作者与文档编写者的**所见即所得 Markdown 编辑工具**：

- 输入 Markdown 语法，即时渲染成富文本（类 Typora 体验）
- 本地优先：数据存浏览器 IndexedDB，离线可用，不强制登录
- 可扩展：遵循 Milkdown「一切皆插件」哲学，AI、协同、同步均为预留扩展点

## 2. 核心原则

1. **WYSIWYG**：输入即渲染，无分屏预览
2. **本地优先**：IndexedDB 为唯一事实源，云同步是可插拔的后续能力
3. **文本可移植**：文档以 Markdown 原文存储（非私有序列化格式），用户永远拥有自己的数据
4. **UI 自绘**：不使用 crepe 成品壳，编辑器 UI 完全自研以贴合产品气质
5. **一切皆插件**：全部功能以插件/模块形式提供，可插拔、可扩展、可开关（详见 04-plugin-design.md）

### M4 图片能力（独立模块）

> 图片是 Typora 类产品第二大交互复杂度模块，且牵涉存储、导出、同步三个方向的架构决策。
> 官方 `@milkdown/plugin-upload`（v7.5.9）提供基础：默认图片转 base64 内嵌，可配置 uploader 接管处理 → 上传抽象层以此为骨架，UI 与存储策略自研。
> **存储策略（三层，用户定稿）**：未配置图床 → 图片另存文档 assets 目录（相对路径引用）或 base64；配置图床 → 上传图床引用远程 URL。
> **纯 Web 约束**：V1 的 assets 目录为 IndexedDB 虚拟目录（浏览器不可写磁盘），渲染经「资源解析器」将相对路径解析为可显示 URL；Tauri 化后映射为真实目录，抽象层不变。
> 灯箱预览（M4.6）为纯 UI 层 L2 模块：本地资源即时渲染、可独立开关，符合插件化理念。

### M5 表格能力（独立模块）

> 表格是编辑器中最复杂的交互模块之一：GFM 专属语法、源码与渲染分离、Excel 数据交换刚需。

## 5. 关键技术决策（草案，待架构文档细化）

| 决策点     | 选择                                                      | 理由                                                                                            |
| ---------- | --------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| 内核包     | @milkdown/kit（不用 crepe）                               | 完全掌控 UI 与插件组合，crepe 是成品壳，定制成本更高                                            |
| 存储格式   | Markdown 原文 + 元数据                                    | 用户数据可移植、可 diff；ProseMirror JSON 仅作运行时态                                          |
| 数据库     | Dexie.js 封装 IndexedDB                                   | 轻量、响应式友好                                                                                |
| 状态管理   | Pinia                                                     | Vue3 标准                                                                                       |
| 组合式工具 | VueUse                                                    | 与 Vue3 组合式 API 配套，编辑体验类功能（防抖/事件）直接复用                                    |
| 应用层 UI  | 自绘为主 + Naive UI 补充                                  | 编辑器区全自绘贴合产品气质；侧边栏/菜单/弹窗用 Naive UI 提效                                    |
| 代码高亮   | **Shiki（已定稿）**                                       | VS Code 同款渲染引擎，视觉顶配；按需懒加载控制体积                                              |
| 数学       | KaTeX                                                     | 快、可离线、视觉佳                                                                              |
| 图表       | mermaid                                                   | 事实标准                                                                                        |
| 测试       | Vitest（单测）+ Playwright（e2e）                         | 编辑器 e2e 必须浏览器级验证                                                                     |
| 工具链     | **Vite+（vp CLI，VoidZero）**                             | 统一 dev/build/lint/fmt/test；生产构建 Vite 8 + Rolldown；e2e(Playwright) 独立（详见 02 §10.5） |
| 功能组织   | 插件化（L1 MilkdownPlugin / L2 AppModule，双层 manifest） | 见 04-plugin-design.md，全功能可插拔/可扩展/可开关                                              |
